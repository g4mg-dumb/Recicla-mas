# 5. Planificación y roles

## Roles sugeridos

| Rol principal | Responsabilidad |
|---|---|
| Coordinación | Carta Gantt, reuniones, seguimiento y riesgos |
| Análisis | Organización, problema, objetivos y requisitos |
| Diseño | Prototipo, navegación e interfaz |
| Datos | Modelo, MySQL, consultas y respaldos |
| Desarrollo e integración | Arquitectura, implementación e integración |

Los roles no son exclusivos. Todos colaboran y cada estudiante debe tener una contribución demostrable.

## Carta Gantt

La planificación debe incluir:

- Tarea.
- Responsable.
- Fecha de inicio.
- Fecha de término.
- Dependencias.
- Estado.
- Evidencia.

## Riesgos

Ejemplos:

- Organización deja de responder.
- Alcance demasiado grande.
- Conflictos de Git.
- Base de datos mal diseñada.
- Dependencia excesiva de un integrante.
- Falta de respaldos.
- Código generado con IA que no funciona.

Cada riesgo debe tener una medida preventiva.

## Reuniones

Se recomienda realizar una reunión breve semanal con acta.

Contenido mínimo:

- Avances.
- Dificultades.
- Decisiones.
- Nuevas tareas.
- Responsables.
- Fecha de revisión.

## Definición de tarea terminada

Una tarea está terminada cuando:

- Cumple el requisito.
- Fue probada.
- Está documentada cuando corresponde.
- Fue subida al repositorio.
- Puede ser demostrada.
